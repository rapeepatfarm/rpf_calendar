# เปิดให้เครื่องอื่นเข้าใช้งาน — ในวง LAN และจากนอกบริษัท

รันสคริปต์นี้เมื่อไรก็ได้เพื่อดูที่อยู่ปัจจุบันและสถานะความปลอดภัย:

```bash
python scripts\show_urls.py
```

---

## 1. ในวง LAN บริษัท — ใช้ได้แล้ว ไม่ต้องตั้งอะไรเพิ่ม

โปรแกรมเปิดรับที่ `0.0.0.0:8200` อยู่แล้ว และ firewall ของเครื่องนี้อนุญาต
`python.exe` ไว้เรียบร้อย จึงเปิดจากมือถือหรือคอมเครื่องอื่นในวงเดียวกันได้ทันที:

```
http://192.168.1.3:8200
```

> ที่อยู่นี้คือไอพีของเครื่องเซิร์ฟเวอร์ ณ วันที่จดเอกสาร
> ถ้าเปิดไม่ติดในอนาคต ให้รัน `scripts\show_urls.py` ดูว่าไอพีเปลี่ยนไปหรือยัง

### ทำให้ไอพีไม่เปลี่ยน (แนะนำให้ทำ)

ไอพีที่ได้จาก DHCP เปลี่ยนได้เมื่อเราเตอร์รีสตาร์ทหรือเครื่องหลุดนานๆ
แล้วทุกคนจะเปิดลิงก์เดิมไม่ได้ · แก้ได้สองทาง เลือกอย่างใดอย่างหนึ่ง

**ก. จองไอพีที่เราเตอร์ (แนะนำ)** — เข้าหน้าตั้งค่าเราเตอร์ หา DHCP Reservation
หรือ Static Lease แล้วผูก MAC address ของเครื่องเซิร์ฟเวอร์กับ `192.168.1.3`
วิธีนี้ดีกว่าเพราะเราเตอร์รู้ตัวว่าไอพีนี้ถูกจองแล้ว จะไม่แจกให้เครื่องอื่นซ้ำ

**ข. ตั้งไอพีคงที่ที่เครื่อง** — Windows Settings → Network → Wi-Fi → IP assignment →
Manual · ต้องกรอก gateway และ DNS ให้ถูกด้วย ถ้ากรอกผิดเครื่องจะเน็ตไม่ติด

### เพิ่มความสะดวก: ใช้ชื่อเครื่องแทนตัวเลข

Windows ตอบชื่อเครื่องผ่าน mDNS อยู่แล้ว ลองเปิด `http://ชื่อเครื่อง.local:8200`
(ดูชื่อเครื่องจาก `hostname`) · ใช้ได้กับ iPhone/iPad/Mac เกือบทุกเครื่อง
ส่วน Android บางรุ่นไม่รองรับ จึงยังควรบอกไอพีสำรองไว้

### หมายเหตุเรื่อง firewall

กฎที่มีอยู่ตอนนี้อนุญาต `python.exe` **ทุกพอร์ต** ในโปรไฟล์ Public
ซึ่งกว้างกว่าที่จำเป็น (โปรแกรม Python อื่นบนเครื่องนี้ก็ถูกอนุญาตไปด้วย)

ถ้าต้องการรัดกุมขึ้น ให้เปิด PowerShell **แบบ Run as Administrator** แล้วสั่ง:

```powershell
New-NetFirewallRule -DisplayName "RPF Calendar 8200" -Direction Inbound -Protocol TCP -LocalPort 8200 -Action Allow -Profile Private
```

แล้วค่อยลบกฎกว้างของ `python.exe` ออก · **ต้องเปลี่ยนโปรไฟล์เน็ตเป็น Private ก่อน**
(ตอนนี้เป็น Public) ไม่งั้นกฎ `-Profile Private` จะไม่ทำงาน:

```powershell
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi 2" -NetworkCategory Private
```

> คำสั่งสองอันนี้เป็นการแก้ไฟร์วอลล์และโปรไฟล์เครือข่ายของเครื่อง
> ผมไม่ได้สั่งให้อัตโนมัติ เพราะควรเป็นคนที่ดูแลเครื่องกดเอง

## 2. หลายโปรแกรมพร้อมกัน (RPF Calendar + Power + Farm + อื่นๆ)

ทั้งสองวิธีรองรับหลายโปรแกรม แต่ต่างกันมากเรื่องความสะดวกของผู้ใช้

### Cloudflare Tunnel — tunnel เดียวเสิร์ฟทุกโปรแกรม

`cloudflared` ตัวเดียวอ่านกฎ ingress แล้วแยกไปตามชื่อโดเมนย่อย:

```yaml
ingress:
  - hostname: calendar.yourdomain.com
    service: http://localhost:8200
  - hostname: power.yourdomain.com
    service: http://localhost:8100
  - hostname: farm.yourdomain.com
    service: http://localhost:8000
  - hostname: feed.yourdomain.com
    service: http://localhost:5000
  - service: http_status:404
```

เพิ่มโปรแกรมใหม่ = เพิ่ม 2 บรรทัด + `cloudflared tunnel route dns` อีกครั้ง
**ไม่ต้องแตะเครื่องผู้ใช้เลย** และ Cloudflare Access คุมสิทธิ์ทุกโปรแกรมจากที่เดียว
(กำหนดได้ด้วยว่าใครเข้าโปรแกรมไหนได้บ้าง)

### Tailscale — ได้เหมือนกัน แต่ผู้ใช้ต้องจำพอร์ต

ลง Tailscale ครั้งเดียวที่เครื่องเซิร์ฟเวอร์ ทุกโปรแกรมเข้าถึงได้ผ่านไอพีเดียวกัน:

```
http://100.x.x.x:8200   RPF Calendar
http://100.x.x.x:8100   RPF Power
http://100.x.x.x:8000   RPF Farm
```

ปัญหาที่จะเจอเมื่อโปรแกรมเยอะขึ้น
- ผู้ใช้ต้องจำว่าโปรแกรมไหนพอร์ตอะไร (หรือทำหน้ารวมลิงก์ไว้)
- **ทุกเครื่องที่จะเข้าต้องลงแอป Tailscale และล็อกอิน** — คูณจำนวนพนักงาน
  ถ้าพนักงานเปลี่ยนเครื่องหรือมีคนเข้าใหม่ ต้องไปตั้งให้ทุกครั้ง
- แยกสิทธิ์รายโปรแกรมไม่ได้ (เข้า tailnet ได้ = เข้าได้ทุกพอร์ต) ต้องไปตั้ง ACL เพิ่ม

### สรุปสำหรับกรณีนี้

**ใช้ Cloudflare Tunnel** — เพราะจะมีหลายโปรแกรมและมีพนักงานหลายคนใช้ผ่านมือถือ
ภาระของ Tailscale อยู่ที่ "ต้องตั้งค่าทุกเครื่อง" ซึ่งโตตามจำนวนคน × จำนวนเครื่อง
ส่วน Cloudflare ตั้งครั้งเดียวที่เซิร์ฟเวอร์ แล้วใครก็เปิดจากเบราว์เซอร์ได้เลย

ค่าใช้จ่าย: Tunnel ฟรี · Access ฟรีถึง 50 ผู้ใช้ · เหลือแค่ **ค่าโดเมนปีละ ~300–500 บาท**

## 3. จากนอกบริษัท — เลือก 1 จาก 3 วิธี

| วิธี | ได้ URL แบบ | ใครเข้าถึงได้ | ต้องลงแอปที่เครื่องผู้ใช้ | เหมาะกับ |
|---|---|---|---|---|
| **Cloudflare Tunnel + Access** | `calendar.yourdomain.com` (https) | เฉพาะอีเมลที่อนุญาต | ไม่ต้อง | **แนะนำ** ถ้ามีโดเมนอยู่แล้ว |
| **Tailscale** | `http://100.x.x.x:8200` | เฉพาะเครื่องในบัญชีเดียวกัน | ต้องลง Tailscale | ทีมเล็ก ไม่มีโดเมน |
| Cloudflare quick tunnel | `xxx.trycloudflare.com` | **ใครก็ได้ที่รู้ URL** | ไม่ต้อง | ทดลองชั่วคราวเท่านั้น |

เครื่องนี้ **มี `cloudflared` ติดตั้งไว้แล้ว** (`C:\Program Files (x86)\cloudflared`)
แต่ยังไม่ได้ตั้งค่าอะไร ส่วน Tailscale ยังไม่ได้ลง

### ก่อนเปิดออกนอกบริษัท ต้องทำ 2 อย่างนี้ก่อนทุกครั้ง

**1. ตั้ง `ONLINE=1` ใน `.env` แล้วรีสตาร์ทโปรแกรม**

```
ONLINE=1
```

ผล: อายุการล็อกอินสั้นลงจาก 14 วันเหลือ 12 ชั่วโมง และโปรแกรมจะ**ไม่ยอมเริ่ม**
ถ้า `SESSION_SECRET` ยังอ่อนแอ

**2. บังคับเปลี่ยนรหัสผ่านแล้ว** — ทุกบัญชีถูกตั้งธง `must_change_password`
ไว้ตั้งแต่ migration 005 · ล็อกอินครั้งถัดไปจะเข้าหน้าอื่นไม่ได้จนกว่าจะตั้งรหัสของตัวเอง
· บัญชีที่ผู้ดูแลสร้างใหม่หรือตั้งรหัสให้ใหม่ ก็ถูกบังคับแบบเดียวกันโดยอัตโนมัติ

โปรแกรมมีตัวกันเดารหัสผ่านด้วย (ผิดเกิน 8 ครั้งใน 15 นาที ล็อก 15 นาที นับแยกต่อไอพี)

### วิธี ก — Cloudflare Tunnel + Cloudflare Access (แนะนำ)

ได้ URL สวยๆ เป็น https และ **ไม่มีอะไรเปิดออกสู่อินเทอร์เน็ตโดยตรง** —
เครื่องที่ฟาร์มเป็นฝ่ายวิ่งออกไปหา Cloudflare เอง ไม่ต้องเปิดพอร์ตที่เราเตอร์
ที่สำคัญคือ **Cloudflare Access จะกั้นด่านตรวจอีเมลไว้ก่อนถึงหน้าล็อกอินของเรา**
คนที่ไม่ได้รับอนุญาตจะไม่เห็นแม้แต่หน้าล็อกอิน (ฟรีถึง 50 ผู้ใช้)

ต้องมี: บัญชี Cloudflare + โดเมนที่ย้าย DNS มาอยู่กับ Cloudflare

```bash
cloudflared tunnel login
```
```bash
cloudflared tunnel create rpf-calendar
```
```bash
cloudflared tunnel route dns rpf-calendar calendar.yourdomain.com
```

สร้างไฟล์ `C:\Users\<ชื่อผู้ใช้>\.cloudflared\config.yml`:

```yaml
tunnel: rpf-calendar
credentials-file: C:\Users\<ชื่อผู้ใช้>\.cloudflared\<tunnel-id>.json

ingress:
  - hostname: calendar.yourdomain.com
    service: http://localhost:8200
  # เผื่ออนาคตเปิด RPF Power ด้วย ใช้ tunnel เดียวกันได้
  # - hostname: power.yourdomain.com
  #   service: http://localhost:8100
  - service: http_status:404
```

ทดลองก่อน:
```bash
cloudflared tunnel run rpf-calendar
```

พอใช้ได้แล้วให้ติดตั้งเป็น Windows Service เพื่อให้ขึ้นเองตอนเครื่องรีสตาร์ท
(ต้องเปิด PowerShell แบบ Administrator):

```powershell
cloudflared service install
```

**แล้วอย่าลืมเปิด Cloudflare Access** — ที่หน้าเว็บ Cloudflare Zero Trust →
Access → Applications → Add an application → Self-hosted → ใส่โดเมนที่ตั้งไว้ →
Policy: Allow เฉพาะอีเมลของคนในบริษัท

ในโหมดนี้ให้ตั้งใน `.env` ด้วย เพราะได้ https จริงจาก Cloudflare:
```
ONLINE=1
SESSION_HTTPS_ONLY=1
```

### วิธี ข — Tailscale (ไม่ต้องมีโดเมน)

วิธีเดียวกับที่ RPF Power ใช้ ดูขั้นตอนละเอียดใน [online-access.md](online-access.md)
สรุปสั้นๆ: ลง Tailscale ที่เครื่องเซิร์ฟเวอร์และที่มือถือ/คอมทุกเครื่องที่จะเข้า
ล็อกอินด้วยบัญชีเดียวกัน แล้วเปิด `http://100.x.x.x:8200`

**ข้อดี** ตั้งง่ายที่สุด ไม่ต้องมีโดเมน ไม่มีอะไรเปิดออกอินเทอร์เน็ตเลย
**ข้อเสีย** ทุกเครื่องที่จะเข้าต้องลงแอปและล็อกอินก่อน — ยุ่งถ้าคนใช้เยอะหรือเปลี่ยนเครื่องบ่อย

ถ้าใช้แบบ `http://100.x.x.x:8200` ธรรมดา **อย่าตั้ง `SESSION_HTTPS_ONLY=1`**
เพราะจะล็อกอินไม่ได้ (Tailscale เข้ารหัสให้ในระดับเครือข่ายอยู่แล้ว)

### วิธี ค — Cloudflare quick tunnel (ใช้อยู่ตอนนี้ · ชั่วคราว)

> **สถานะ: เปิด quick tunnel ไว้แล้ว**
> ดู URL ปัจจุบันด้วย `python scripts\show_urls.py`

**คำสั่งจัดการ tunnel** (หรือดับเบิลคลิก `start_tunnel.bat` เอาก็ได้)

| สั่ง | ทำอะไร |
|---|---|
| `start_tunnel.bat` | เปิด · ถ้ามีตัวเดิมรันอยู่แล้วจะบอก URL เดิมให้ ไม่เปิดซ้อน |
| `start_tunnel.bat restart` | ปิดตัวเดิมแล้วเปิดใหม่ — **ได้ URL ใหม่ ต้องแจ้งทุกคน** |
| `start_tunnel.bat stop` | ปิด tunnel |

> เปิดซ้อนกันไม่ได้ — cloudflared สองตัวจะแย่งไฟล์ `cloudflared.log` กัน
> แล้วสคริปต์จะอ่าน URL เก่ามาแสดงผิด · สคริปต์จึงเช็คให้ก่อนทุกครั้ง
> เปิดใหม่เมื่อเครื่องรีสตาร์ทด้วย `start_tunnel.bat` (URL จะเปลี่ยน)
> หยุดด้วย `taskkill /IM cloudflared.exe /F`

```bash
cloudflared tunnel --url http://localhost:8200
```

ได้ URL แบบ `https://random-words.trycloudflare.com` ทันทีโดยไม่ต้องมีบัญชี

**อย่าใช้ระยะยาว** เพราะ
- URL เปลี่ยนทุกครั้งที่รีสตาร์ท
- **ใครที่รู้ URL ก็เปิดหน้าล็อกอินได้** เหลือแต่รหัสผ่านกั้นอยู่ชั้นเดียว
- Cloudflare ไม่รับประกันความเสถียรของ quick tunnel

## 4. ทำไมไม่ใช้ Vercel (หรือ Netlify / Render ฟรีทีเออร์)

Vercel ทำงานได้ดีกับเว็บที่ไม่มีสถานะ แต่ไม่เข้ากับโปรแกรมนี้ในหลายจุดที่สำคัญ

| เรื่อง | ปัญหาที่จะเจอ |
|---|---|
| **ตัวสร้างงานล่วงหน้า** | `services/scheduler.py` เป็นงานเบื้องหลังที่ต้องรันค้างไว้ตลอดและตื่นทุกวันตอนตี 0:05 · Vercel เป็น serverless ไม่มีโปรเซสที่รันค้าง — ฟังก์ชันตายทันทีที่ตอบ request เสร็จ แผนงานประจำจะไม่ถูกสร้าง |
| **ฐานข้อมูล** | ต้องย้าย PostgreSQL ขึ้นคลาวด์ด้วย = **ข้อมูลงานฟาร์มออกไปอยู่นอกบริษัท** และมีค่าใช้จ่ายรายเดือน |
| **connection pool** | `database.py` ใช้ `ThreadedConnectionPool` ซึ่งอาศัยว่าโปรเซสอยู่ยาว · บน serverless ทุก request อาจเป็นโปรเซสใหม่ ต้องรื้อไปใช้ pooler ภายนอกแทน |
| **เฟส 5 (ซิงค์วัคซีนจาก RPF Farm)** | DB ของ rpf_farm / rpf_feed อยู่บนเครื่องที่ฟาร์มในวง `192.168.1.x` · แอปบนคลาวด์เข้าไม่ถึงอยู่ดี ต้องทำ tunnel กลับมาที่ฟาร์มอีกที — กลายเป็นซับซ้อนกว่าเดิม |
| **ตัวกันเดารหัสผ่าน** | `services/loginguard.py` นับในหน่วยความจำของโปรเซส · บน serverless ที่โปรเซสเกิด-ตายตลอด ตัวนับจะรีเซ็ตเองเรื่อยๆ กันอะไรไม่ได้ |
| **cold start** | ผู้ใช้กดเปิดหน้าแรกจะรอ 1–3 วินาที ทุกครั้งที่ไม่มีคนใช้มาสักพัก |

**สรุป** ใช้ Vercel ได้ก็ต่อเมื่อยอมรื้อสถาปัตยกรรม (ย้าย DB ขึ้นคลาวด์ +
ย้ายงานเบื้องหลังไปเป็น cron ภายนอก + เลิกซิงค์กับโปรแกรมอื่นในฟาร์ม)
ซึ่งได้ผลลัพธ์แย่กว่า Cloudflare Tunnel ที่ทำงานได้เลยโดยไม่ต้องแก้โค้ดแม้บรรทัดเดียว
และข้อมูลยังอยู่ในบริษัท

**Cloudflare Tunnel เทียบกับ Vercel** — ได้ https URL สวยเหมือนกัน ฟรีเหมือนกัน
แต่โค้ดไม่ต้องแก้ ข้อมูลไม่ต้องย้าย และมี Cloudflare Access กั้นด่านให้ฟรีอีกชั้น

## 5. สิ่งที่ต้องระวังเมื่อเปิดออกนอกบริษัท

- **เครื่องที่ฟาร์มต้องเปิดตลอด** ถ้าปิดหรือเน็ตหลุด จะเข้าจากภายนอกไม่ได้
- **ให้สิทธิ์เท่าที่จำเป็น** — คนที่ดูอย่างเดียวใช้ `viewer` · คนที่ต้องกดเริ่ม/จบงาน
  ของตัวเองใช้ `worker` · อย่าแจก `admin` ให้ใครที่ไม่ได้ดูแลระบบ
- **อย่าเปิดพอร์ตที่เราเตอร์ (port forwarding)** โปรแกรมนี้ไม่มี TLS ในตัวและ
  ไม่ได้ออกแบบมาให้รับการยิงจากอินเทอร์เน็ตโดยตรง — ใช้ tunnel เท่านั้น
- **สำรองฐานข้อมูล** ก่อนเปิดให้คนนอกเข้าใช้:
  ```bash
  pg_dump -U postgres -d rpf_calendar -F c -f D:\RPF_Systems\backups\rpf_calendar.dump
  ```
